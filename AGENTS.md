# AGENTS.md

Файл для AI-агентов, работающих с этим репозиторием. Новый код и документацию пишем на английском.

## Обзор проекта

`the-new-rule` — консольная текстовая игра «Симулятор государства»: игрок правит вымышленной страной 192 недели (48 месяцев). Игрок вводит свободный текст действия (на языке рана), LLM превращает его в строгий JSON с числовыми последствиями, а детерминированный движок применяет эффекты, крутит экономические/социальные формулы и ведёт кризисные арки и концовки.

- Стек: TypeScript (строгий режим), ESM (`"type": "module"`), Node.js. Запуск через `tsx`, шага сборки нет (`tsc --noEmit`, эмиссия отключена).
- Зависимости: `openai` (OpenAI-совместимый SDK; используется для DeepSeek, отличается только `baseURL`), `zod` (валидация выхлопа LLM), `dotenv`.
- Dev-зависимости: `tsx`, `typescript`, `vitest`, `@types/node`.
- Два режима игры: `realism` (последствия как в реальном мире) и `creative` («креативизм»: мир играет вместе с игроком, абсурд — бонус к счёту).
- Три языка рана (интерфейс и вывод LLM): русский / українська / english — выбираются при старте, весь текст игрока идёт через словарь `i18n.ts`.
- Сеттинг мира: свободный текст игрока (1–3 предложения; пусто = современность), хранится в состоянии рана и подставляется первой строкой в каждый промпт LLM. Влияет только на тексты.

## Команды

```bash
npm install          # установить зависимости
npm run dev          # запустить игру (tsx game.ts)
npm test             # тесты (vitest run)
npm run typecheck    # проверка типов (tsc --noEmit), сборки/эмиссии нет
```

Перед запуском нужен `.env` (шаблон — `.env.example`):

- `USE_MOCK_LLM=true` — игра полностью работает офлайн на эвристической заглушке `MockLLM` (для разработки и тестов руками).
- Иначе: `DEEPSEEK_API_KEY`, `DEEPSEEK_BASE_URL` (по умолчанию `https://api.deepseek.com`), `DEEPSEEK_MODEL` (по умолчанию `deepseek-chat`).

Процесса деплоя нет — это локальная консольная игра.

## Архитектура

Разделение строгое: **движок (`engine/`) ничего не знает про LLM и про язык**, слой LLM (`llm/`) импортирует движок, а не наоборот. Оркестрация и консольный UI — в `game.ts`. Вся локализация — в `i18n.ts` (UI-строки, языковые блоки промптов, заглушки MockLLM).

- `game.ts` — точка входа: консольный цикл игры (собственная очередь строк поверх readline), старт рана (название → язык → сеттинг → режим), один ход (действие → тик → арки → новости), финал со счётом и эпилогом. Команды локализованы (`статус`/`status`, `сеттинг`/`setting` — печатает сеттинг рана, `сдаться`/`surrender`, `пропустить N`/`skip N`).
- `i18n.ts` — **словарь локализации**: `UI_STRINGS` (весь UI на трёх языках), `PROMPT_STRINGS` (системные инструкции и метки user-сообщений промптов), `MOCK_STRINGS` (заглушки), `LANGUAGE_MENU` (трёхъязычное меню выбора языка). Движок и валидатор этот модуль не импортируют.
- `engine/config.ts` — **весь баланс игры** (спецификация 7.1–7.9): статы, слои настроения и пояса, капы валидатора, формулы тика, жёсткие арки, базовые ивенты, концовки и счёт. Все ключи — `as const`-массивы (`STAT_KEYS`, `MOOD_KEYS`, `IDEOLOGY_TAGS`), типы выводятся из них.
- `engine/state.ts` — `GameState`, начальное состояние, пояса настроений, применение дельт (клэмпинг 0..100, усилитель реакции, заморозка импичмента), низкоуровневые операции с арками, применение действий и динамических событий. В состоянии лежит `setting` (сеттинг рана — свободный текст, движок его не интерпретирует).
- `engine/tick.ts` — недельный тик по формулам 7.5 (экономика, технологии, образование, казна, настроения слоёв, жилищный пузырь, бездомность, население, эмиграция, соседи). `rng` внедряется параметром для детерминированных тестов.
- `engine/triggers.ts` — жёсткие кризисные арки (переворот, протесты, олигархи, вторжение), развязки по стадиям, война по инициативе игрока (`actionType: "war"`), продвижение арок раз за ход.
- `engine/events.ts` — базовые ивенты: эффекты фиксированы в конфиге и применяет только движок; LLM лишь переписывает название/описание (flavor).
- `engine/validator.ts` — предохранитель между LLM и движком (Zod): толерантные схемы, отбрасывание неизвестных ключей, клэмпинг до потолков режима (`CONFIG.caps`), битый ответ = нейтральный результат без падения игры.
- `engine/score.ts` — концовки и итоговый счёт (7.9), разрешение конца срока, попытка остаться у власти.
- `engine/chronicle.ts` — хроника (лимит записей + сводный счётчик схлопнутых) и реестр персонажей.
- `llm/client.ts` — интерфейс `LLM`, `DeepSeekLLM` (openai SDK, JSON-ответ, стрип код-фенсов, ошибки → `null`), `CachedLLM` (кэш парсинга действий по нормализованному lowercase-тексту), `MockLLM` (заглушка по ключевым словам трёх языков, строки — на языке рана), фабрика `createLLM(lang)` по переменным окружения.
- `llm/prompts.ts` — промпты раздела 8 спецификации (парсинг действия, narrate-ответ «новости + flavor + динамическое событие», эпилог). Статичная часть — в начале промпта, переменные — в конце user-сообщения. Язык рана — параметр: системные инструкции и метки собираются из `PROMPT_STRINGS`; **сеттинг — всегда первая строка user-сообщения**; схемы ответа (`PARSE_SCHEMA`, `NARRATE_SCHEMA`) — единые для всех языков.

## Ключевые инварианты (законы проекта)

1. **Баланс только в `engine/config.ts`.** Числа из конфига запрещено хардкодить в логике — только импорт отсюда. Комментарии ссылаются на пункты спецификации (7.1–7.9) — сохраняйте эти ссылки.
2. **Движок не импортирует LLM-слой и `i18n.ts`.** Весь выхлоп LLM проходит через валидатор; движок и валидатор языка не знают вовсе.
3. **Битый ответ LLM не роняет игру.** Сеть/парсинг упали → `null` → валидатор отдаёт нейтральный результат.
4. **Динамические события** не трогают абсурд и не завершают игру — это гарантируется конструктором схемы (таких полей нет).
5. **Фиксированные эффекты применяет движок**, а не LLM: базовые ивенты, потолки капов, развязки арок.
6. Все шкалы клэмпятся (`clampStat`, `CONFIG.statScale`); казна может уходить в минус, но не в `NaN`.
7. **Ключи JSON-схемы не переводятся никогда**: `summary`, `effects`, `actionType`, `warTarget`, `news`, `dynamicEvent`, `epilogue` и т.д. всегда английские при любом языке рана — язык меняет только строки-значения. Схемы в `llm/prompts.ts` — общие для всех языков.
8. **Сеттинг влияет только на тексты**: названия ивентов, персонажей, новостей, интерпретацию действий. Он не может менять числа за пределами валидатора, отключать триггеры или менять правила движка; id и ключи соседей/персонажей неизменны.

## Тесты

- Фреймворк — Vitest, файлы в `tests/` зеркалят модули движка и LLM-слоя: `tick`, `triggers`, `validator`, `score`, `chronicle`, `derived`, `prompts`. Тесты чисто детерминированные — без LLM-API и сети (MockLLM допустим).
- `tests/helpers.ts`: `makeState(mode, tweak)` — быстрое создание состояния; `noEventRng` (всегда 1, ивент не выпадает) и `forceEventRng` (всегда 0, ивент выпадает) — управление случайностью тика.
- Имена тестов ссылаются на номера сценариев спецификации («Тесты 2, 6, 7, 8, 9») — новые тесты сценариев называйте по тому же принципу.
- Перед сдачей изменений прогоняйте `npm test` и `npm run typecheck` — обе команды должны быть зелёными.

## Стиль кода

- ESM: относительные импорты с расширением `.js` (module resolution `NodeNext`), `import 'dotenv/config'` только в точке входа.
- TypeScript `strict`: `as const` для конфигов, типы выводятся из массивов ключей; интерфейсы состояния экспортируются из `engine/state.ts`.
- Отступ 2 пробела, одинарные кавычки, точки с запятой, функции-стрелки для мелких помощников.
- Комментарии — на английском (см. шапку файла), ссылкаются на пункты спецификации (7.x) и «законы».
- Все строки, которые видит игрок, и языковые блоки промптов — только через словарь `i18n.ts` (три языка: `ru`, `uk`, `en`); UI-строки в код не хардкодим.

## Безопасность

- API-ключ хранится только в `.env` (файл в `.gitignore`); в репозиторий попадает лишь `.env.example` без реальных значений. Никогда не коммитьте `.env`.
- Выхлоп LLM считается недоверенным: каждый ответ проходит Zod-схему, клэмпится до капов режима и отбрасывает неизвестные ключи — производные показатели (бездомность, пузырь, население) через LLM изменить нельзя. Язык рана и сеттинг правил движка не меняют (законы 2, 7, 8).
