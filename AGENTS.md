# AGENTS.md

Файл для AI-агентов, работающих с этим репозиторием. Новый код и документацию пишем на английском.

## Обзор проекта

`the-new-rule` — консольная текстовая игра «Симулятор государства»: игрок правит вымышленной страной 192 недели (48 месяцев). Игрок вводит свободный текст действия (на языке рана), LLM превращает его в строгий JSON с числовыми последствиями, а детерминированный движок применяет эффекты, крутит экономические/социальные формулы и ведёт кризисные арки и концовки.

- Стек: TypeScript (строгий режим), ESM (`"type": "module"`), Node.js. Запуск через `tsx`, шага сборки нет (`tsc --noEmit`, эмиссия отключена).
- Зависимости: `openai` (OpenAI-совместимый SDK; используется для DeepSeek, отличается только `baseURL`), `zod` (валидация выхлопа LLM), `dotenv`.
- Dev-зависимости: `tsx`, `typescript`, `vitest`, `@types/node`.
- Два режима игры: `realism` (последствия как в реальном мире) и `creative` («креативизм»: мир играет вместе с игроком, абсурд — бонус к счёту).
- Три языка рана (интерфейс и вывод LLM): русский / українська / english — выбираются при старте, весь текст игрока идёт через словарь `i18n.ts`.
- Сеттинг мира: свободный текст игрока (1–3 предложения; пусто = современность), хранится в состоянии рана и подставляется первой строкой в каждый промпт LLM. Влияет только на тексты.

## Команды

```bash
npm install          # установить зависимости
npm run dev          # запустить игру (tsx game.ts)
npm run demo         # headless-демо ран для записи гифок (tsx demo/demo.ts)
npm test             # тесты (vitest run)
npm run typecheck    # проверка типов (tsc --noEmit), сборки/эмиссии нет
```

`npm run demo` работает без интерактивного ввода и без API-ключа: по умолчанию MockLLM принудительно включается даже при `USE_MOCK_LLM=false` в `.env`. Флаги: `--live` (настоящие запросы к LLM, нужен `DEEPSEEK_API_KEY`, без него — понятная ошибка и exit code ≠ 0), `--delay <мс>` (пауза между ходами для записи экрана), `--lang ru|uk|en`, `--out <файл>` (транскрипт в файл), `--seed <n>` (seeded RNG; по умолчанию фиксирован, так что демо воспроизводимо потранскриптно). Кэш парсинга действий в `--live` — как в обычной игре. Демо не трогает сейвы. Сценарий рана — в `demo/script.ts`.

Перед запуском нужен `.env` (шаблон — `.env.example`):

- `USE_MOCK_LLM=true` — игра полностью работает офлайн на эвристической заглушке `MockLLM` (для разработки и тестов руками).
- Иначе: `DEEPSEEK_API_KEY`, `DEEPSEEK_BASE_URL` (по умолчанию `https://api.deepseek.com`), `DEEPSEEK_MODEL` (по умолчанию `deepseek-chat`).

Процесса деплоя нет — это локальная консольная игра.

## Архитектура

Разделение строгое: **движок (`engine/`) ничего не знает про LLM и про язык**, слой LLM (`llm/`) импортирует движок, а не наоборот. Оркестрация и консольный UI — в `game.ts`. Вся локализация — в `i18n.ts` (UI-строки, языковые блоки промптов, заглушки MockLLM).

- `game.ts` — точка входа: консольный цикл игры (собственная очередь строк поверх readline), старт рана (название → автосейв? → язык → сеттинг → режим), один ход (действие → тик → арки → новости → автосейв), финал со счётом и эпилогом. Команды локализованы (`статус`/`status`, `сеттинг`/`setting` — печатает сеттинг рана, `сохранить`/`save`, `сохранить и выйти`/`save and quit`, `сдаться`/`surrender`, `пропустить N`/`skip N`). Граница локализации: `game.ts` разрешает свободный текст цели войны в id соседа (по именам всех языков) и рендерит ключи движка через `i18n.ts`. Хелперы вывода (`printBanner`, `printStatus`, `playTurn`, `finale`) экспортированы: их переиспользует headless-демо (`demo/run.ts`), а `main()` запускается только когда `game.ts` — точка входа (проверка `import.meta.url`); `playTurn` принимает опциональный `rng` (по умолчанию `Math.random`).
- `save.ts` — **сохранения и транскрипт** (7.10): `tee`/`teeInput` («тройник»: консоль + буфер транскрипта), `saveGame`/`loadGame` (JSON `{version, savedAt, state, transcript}`, `SAVE_VERSION = 2`; несовпадение version — `VersionMismatchError` с локализованным сообщением, не краш; сейвы версии 1 не загружаются — состояние перешло на языконейтральные ключи), `autosavePath`/`savePathFor`. Весь вывод игры идёт через `tee`, весь ввод игрока — через `teeInput`.
- `i18n.ts` — **словарь локализации**: `UI_STRINGS` (весь UI на трёх языках), `PROMPT_STRINGS` (системные инструкции и метки user-сообщений промптов, шаблоны рендера хроники), `MOCK_STRINGS` (заглушки), `LANGUAGE_MENU` (трёхъязычное меню выбора языка). Движок и валидатор этот модуль не импортируют. Содержит также **словари строк движка** (`NEIGHBOR_NAMES`, `BASE_EVENT_TITLES`, `HARD_ARC_TITLES`) и **рендереры** его сообщений: `neighborName`, `baseEventTitle`, `arcTitle`, `renderArcOutcome`, `renderChronicleEntry`, `renderHappening`, `renderEndingReason`/`renderEndingDescription` — движок отдаёт ключи, текст для игрока собирается только здесь.
- `engine/config.ts` — **весь баланс игры** (спецификация 7.1–7.9): статы, слои настроения и пояса, капы валидатора, формулы тика, жёсткие арки, базовые ивенты, концовки и счёт. Все ключи — `as const`-массивы (`STAT_KEYS`, `MOOD_KEYS`, `IDEOLOGY_TAGS`, `HARD_ARC_IDS`), типы выводятся из них. Баланс — только числа и ключи: у соседей и базовых ивентов есть стабильные `id`, но нет строк для игрока (они живут в `i18n.ts`).
- `engine/state.ts` — `GameState`, начальное состояние, пояса настроений, применение дельт (клэмпинг 0..100, усилитель реакции, заморозка импичмента), низкоуровневые операции с арками, применение действий и динамических событий. Соседи идентифицируются `id` (имя — в `i18n.ts`), `warTarget` арок — id соседа. В состоянии лежит `setting` (сеттинг рана — свободный текст, движок его не интерпретирует).
- `engine/tick.ts` — недельный тик по формулам 7.5 (экономика, технологии, образование, казна, настроения слоёв, жилищный пузырь, бездомность, население, эмиграция, соседи). `rng` внедряется параметром для детерминированных тестов.
- `engine/triggers.ts` — жёсткие кризисные арки (переворот, протесты, олигархи, вторжение), развязки по стадиям, война по инициативе игрока (`actionType: "war"`, цель — id соседа), продвижение арок раз за ход. Новости развязок — не строки, а ключи `HappeningMsg`; `HARD_TRIGGERS` не содержат названий (только проверки условий).
- `engine/events.ts` — базовые ивенты: скелеты (id + условия + эффекты) фиксированы в конфиге и применяет только движок; LLM лишь переписывает название/описание (flavor), исходное название берётся из `i18n.ts` на языке рана.
- `engine/validator.ts` — предохранитель между LLM и движком (Zod): толерантные схемы, отбрасывание неизвестных ключей, клэмпинг до потолков режима (`CONFIG.caps`), битый ответ = нейтральный результат без падения игры. Пустой `summary` допустим — локализованный дефолт показывает UI-слой.
- `engine/score.ts` — концовки и итоговый счёт (7.9), разрешение конца срока, попытка остаться у власти. Описания концовок — ключи `EndingReason`, а не готовый текст; подписи концовок для игрока — в `i18n.ts` (`finale.endingLabels`).
- `engine/chronicle.ts` — хроника (лимит записей + сводный счётчик схлопнутых) и реестр персонажей. Записи — структурированные ключи `ChronicleEntry` (движок языка не знает); plain-строки в хронике — наследие сейвов версии 1, рендерер пропускает их как есть.
- `llm/client.ts` — интерфейс `LLM`, `DeepSeekLLM` (openai SDK, JSON-ответ, стрип код-фенсов, ошибки → `null`), `CachedLLM` (кэш парсинга действий по нормализованному lowercase-тексту), `MockLLM` (заглушка по ключевым словам трёх языков, строки — на языке рана), фабрика `createLLM(lang)` по переменным окружения.
- `llm/prompts.ts` — промпты раздела 8 спецификации (парсинг действия, narrate-ответ «новости + flavor + динамическое событие», эпилог). Статичная часть — в начале промпта, переменные — в конце user-сообщения. Язык рана — параметр: системные инструкции и метки собираются из `PROMPT_STRINGS`; **сеттинг — всегда первая строка user-сообщения**; схемы ответа (`PARSE_SCHEMA`, `NARRATE_SCHEMA`) — единые для всех языков. Контекст рендерится на языке рана: соседи — с именами из `NEIGHBOR_NAMES`, хроника — через `renderChronicleEntry`, названия арок — через `arcTitle`.
- `demo/` — **headless-демо** для записи геймплейных гифок. `demo/demo.ts` — CLI-вход (разбор флагов, `--out`); `demo/run.ts` — `runDemo(options)`: гонит `demo/script.ts` (название, режим, язык, сеттинг, шаги `{action}`/`{skip}`) через экспортированные `printBanner`/`printStatus`/`playTurn`/`finale`, без readline и без сейвов, и возвращает транскрипт. `demo/rng.ts` — mulberry32 seeded RNG: один инстанс кормит и движок (через новый параметр `rng` у `playTurn`), и MockLLM, так что прогон с фиксированным `--seed` воспроизводит транскрипт побайтово. По умолчанию MockLLM принудителен (`USE_MOCK_LLM` ставится и восстанавливается на время прогона); `--live` требует `DEEPSEEK_API_KEY` и идёт через `createLLM` (с кэшем действий), воспроизводимость текстов LLM не гарантируется.

## Ключевые инварианты (законы проекта)

1. **Баланс только в `engine/config.ts`.** Числа из конфига запрещено хардкодить в логике — только импорт отсюда. Комментарии ссылаются на пункты спецификации (7.1–7.9) — сохраняйте эти ссылки.
2. **Движок не импортирует LLM-слой и `i18n.ts`.** Весь выхлоп LLM проходит через валидатор; движок и валидатор языка не знают вовсе. Следствие: движок никогда не хранит и не печатает строки для игрока — только стабильные id и ключи сообщений (`ChronicleEntry`, `HappeningMsg`, `EndingReason`, id соседей/ивентов/арок). Любая новая строка для игрока от движка — ключ в этих типах плюс шаблоны во всех трёх языках в `i18n.ts`.
3. **Битый ответ LLM не роняет игру.** Сеть/парсинг упали → `null` → валидатор отдаёт нейтральный результат.
4. **Динамические события** не трогают абсурд и не завершают игру — это гарантируется конструктором схемы (таких полей нет).
5. **Фиксированные эффекты применяет движок**, а не LLM: базовые ивенты, потолки капов, развязки арок.
6. Все шкалы клэмпятся (`clampStat`, `CONFIG.statScale`); казна может уходить в минус, но не в `NaN`.
7. **Ключи JSON-схемы не переводятся никогда**: `summary`, `effects`, `actionType`, `warTarget`, `news`, `dynamicEvent`, `epilogue` и т.д. всегда английские при любом языке рана — язык меняет только строки-значения. Схемы в `llm/prompts.ts` — общие для всех языков.
8. **Сеттинг влияет только на тексты**: названия ивентов, персонажей, новостей, интерпретацию действий. Он не может менять числа за пределами валидатора, отключать триггеры или менять правила движка; id и ключи соседей/персонажей неизменны.

## Тесты

- Фреймворк — Vitest, файлы в `tests/` зеркалят модули движка и LLM-слоя: `tick`, `triggers`, `validator`, `score`, `chronicle`, `derived`, `prompts`, `arcs` (дедуп арок и стадии, 7.8.1), `save` (save/load и транскрипт, 7.10), `i18n` (рендер строк движка на языке рана — регрессия «английский ран не показывает русские названия»). Тесты чисто детерминированные — без LLM-API и сети (MockLLM допустим).
- `tests/helpers.ts`: `makeState(mode, tweak)` — быстрое создание состояния; `noEventRng` (всегда 1, ивент не выпадает) и `forceEventRng` (всегда 0, ивент выпадает) — управление случайностью тика.
- `demo` (headless-демо): фиксированный seed даёт идентичный транскрипт на двух прогонах (MockLLM-режим; для `--live` воспроизводимость не гарантируется и не тестируется), транскрипт содержит газету, арку и финальный счёт, `--live` без `DEEPSEEK_API_KEY` — понятная ошибка без краша.
- Имена тестов ссылаются на номера сценариев спецификации («Тесты 2, 6, 7, 8, 9») — новые тесты сценариев называйте по тому же принципу.
- Перед сдачей изменений прогоняйте `npm test` и `npm run typecheck` — обе команды должны быть зелёными.

## Стиль кода

- ESM: относительные импорты с расширением `.js` (module resolution `NodeNext`), `import 'dotenv/config'` только в точке входа.
- TypeScript `strict`: `as const` для конфигов, типы выводятся из массивов ключей; интерфейсы состояния экспортируются из `engine/state.ts`.
- Отступ 2 пробела, одинарные кавычки, точки с запятой, функции-стрелки для мелких помощников.
- Комментарии — на английском (см. шапку файла), ссылкаются на пункты спецификации (7.x) и «законы».
- Все строки, которые видит игрок, и языковые блоки промптов — только через словарь `i18n.ts` (три языка: `ru`, `uk`, `en`); UI-строки в код не хардкодим.

## Безопасность

- API-ключ хранится только в `.env` (файл в `.gitignore`); в репозиторий попадает лишь `.env.example` без реальных значений. Никогда не коммитьте `.env`.
- Выхлоп LLM считается недоверенным: каждый ответ проходит Zod-схему, клэмпится до капов режима и отбрасывает неизвестные ключи — производные показатели (бездомность, пузырь, население) через LLM изменить нельзя. Язык рана и сеттинг правил движка не меняют (законы 2, 7, 8).
